# Tugboat FFI: the Kotlin API of the phone core

Generated by UniFFI 0.32.2 from `crates/ffi` into
`app/src/main/java/uniffi/tugboat_ffi/tugboat_ffi.kt` (package `uniffi.tugboat_ffi`,
native library `libtugboat_ffi.so`, loaded by JNA as `tugboat_ffi`). Never edit the .kt file:
`apps\android\build-rust.cmd` regenerates it. This page lists the API exactly as generated.

Gradle needs: `net.java.dev.jna:jna:5.17.0@aar` (the version the bindings were built against). The bindings use no
coroutines. `.so` files: `app/src/main/jniLibs/arm64-v8a` and `x86_64`, only `libtugboat_ffi.so`.

## Rules for calling it

1. Every method is a plain blocking call. Call it from `Dispatchers.IO` or a worker thread. Never
   from the main thread, and never from inside `EventListener.onEvent` (the callback runs on a
   Rust runtime thread; calling `startNetwork`, `stopNetwork`, `pairWith` or `unpair` there
   panics).
2. Slow calls: `startNetwork` (binds the endpoint), `stopNetwork`, `unpair` (up to 3 s while the
   PC is told), `pairWith` (until the PC owner clicks Pair, about 2 min at most, or the dial
   bound of 8 s on the wrong network), `addFile` (copies and hashes the file: tens of ms for a
   photo, seconds for a long video; it holds the database lock while it copies, so sync stalls
   for that long). Everything else only reads or writes SQLite.
3. `onEvent` must return at once: post to your own scope. A throwing listener does not kill the
   pump (the event is dropped and logged).
4. Ids are strings: items and folders are hyphenated UUIDs, devices are 64 hex chars. Times are
   unix milliseconds (`Long`). Sizes and byte counts are `ULong`, counts are `UInt`
   (Kotlin unsigned types).
5. Errors are `SnapException` subclasses (below). `e.message` is already one readable line.
6. `PhoneCore` is `AutoCloseable`. Call `stopNetwork()` then `close()`. Dropping it is safe from
   any thread. One `PhoneCore` per process (the log file and the database are per data dir).
7. The secret key: `PhoneConfig.secretKey` is the 32-byte iroh key. Create it once with
   `generateSecretKey()`, wrap it with an Android Keystore AES-GCM key, store only the wrapped
   bytes, unwrap it for `PhoneCore.open`. Core never writes it to disk.
8. `addFile` COPIES the source into app storage. Delete the source (cacheDir) afterwards.

## Entry points

```kotlin
// top-level functions in package uniffi.tugboat_ffi
@Throws(SnapException::class) fun generateSecretKey(): kotlin.ByteArray
@Throws(SnapException::class) fun inspectPairingPayload(payload: kotlin.String): PairingPreview

// PhoneCore.Companion
@Throws(SnapException::class) fun open(config: PhoneConfig, listener: EventListener): PhoneCore
```

`inspectPairingPayload` checks a scanned QR text or deep link without touching the network:
`PairBadPayload` for anything that is not a Tugboat pairing code (including one naming a
non-local address). Use it in the scanner (ignore other QR codes) and in the deep-link
"Pair with this PC?" dialog (it gives the PC name and address).

```kotlin
    fun logPath(): kotlin.String

    fun restoreItem(id: kotlin.String)

    fun saveSettings(settings: Settings)

```
Only `deviceId`, `logPath`, `reconnectNow`, `cancelPairing`, `status` and `stopNetwork` cannot
throw; every other method carries `@Throws(SnapException::class)` in the generated class.

| Method | What it does |
|---|---|
| `open` | Logging, database (backup, migrate; a newer database is refused with `NewerDatabase`), default folders Inbox / Keep / Unsorted, one Bin sweep, event pump, ticker (Bin sweep and pairing expiry at the core's next due time, at most 60 s apart). Does not touch the network. |
| `deviceId` | This phone's public key, 64 hex chars. |
| `logPath` | Current log file. `<path>.1` and `<path>.2` are the older rotated files (5 MB each, three kept). "Export log" shares all that exist, oldest first. |
| `freeSpaceBytes` | Free bytes on the volume holding phone copies. Used for Settings' storage line and for refusing a shared file that does not fit. The storage guard itself is enforced by the core since 0.2.0 (downloads stop below `Settings.storageGuardBytes`); the banner follows `SyncStatus.storageLow`, not this number. |
| `startNetwork(mdns)` | Starts the endpoint (binds `0.0.0.0`, random UDP port) and the connect loop to the paired PC (cached addresses first, `mdns` = then look it up by name). `Invalid` if already started. |
| `stopNetwork` | Stops it. |
| `reconnectNow` | Wi-Fi changed or app came to the front: dial the PC now instead of waiting out the back-off (up to 30 s). Safe any time. |
| `status` | `SyncStatus`, see below. Events keep it current; call it once on screen start. |
| `pairWith(payload)` | Blocks until paired. The listener gets `PairingCode` first: show it large ("Check your PC shows 482 913"). On success the phone connects to the PC by itself. |
| `cancelPairing` | Releases a waiting `pairWith` with `PairCancelled`. No effect when nothing waits. |
| `pairedPc` | The paired PC or null. |
| `unpair` | Unpairs. Files stay. If the PC cannot be told now, the phone keeps a notice and delivers it later; `status().message` says "PC NOT TOLD YET ..." meanwhile. `NotPaired` if nothing is paired. |
| `folders` | Folders with item counts and retention (`retentionSecs == null` is Keep). |
| `items(folderIdFilter, bin, after, limit)` | Newest first. `folderIdFilter` null = all. `bin` true = only Bin items. `after` = `ItemPage.next` of the previous page. `limit` 0 = 50, max 500. |
| `item(id)` | One item or null. |
| `addFile(file)` | Takes a captured or imported file in. Returns the new item id. Record and sync trigger are done when it returns; the file reaches the PC in the background. |
| `setPinned` | Keep / un-keep. A kept item never expires. |
| `moveItem` | Move to another folder; its retention clock restarts there. |
| `deleteItem` | To the Bin, restorable for `Settings.binDays`. |
| `restoreItem` | From the Bin with a fresh full retention. A file already purged here is fetched from the PC (`local == PENDING` until it arrives). |
| `routeCapture(fix)` | Camera routing, see `CaptureRoute`. The core uses the fix only if `ageMs` < 2 min and `accuracyM` <= 100; smallest radius wins. |
| `activity(before, limit)` | Newest first. `before` = last `id` of the previous page. |
| `settings` / `saveSettings` | Values are validated by core (`Invalid` for nonsense, the old value stays). |

Not exported yet: creating, renaming and deleting folders, retention changes and places editing
(`put_place`). Add them as thin passthroughs when a screen needs them.

## Data types

```kotlin
data class PhoneConfig(
    var dataDir: kotlin.String,        // filesDir: db, thumbs, logs, held files all live under it

data class FolderInfo(
    var id: kotlin.String,
    var kind: FolderKind,

)

data class ItemInfo(

)

data class ItemPage(var rows: List<ItemInfo>, var next: kotlin.String?)   // next == null = last page

data class ActivityInfo(
    var id: kotlin.Long,
    var atMs: kotlin.Long,
    var itemId: kotlin.String?,
    var action: ActivityAction,
    var detail: kotlin.String          // short text, e.g. "Inbox"
)

data class PairedPc(
    var id: kotlin.String,
    var name: kotlin.String,
    var pairedAtMs: kotlin.Long?,
    var lastSeenAtMs: kotlin.Long?,
    var addresses: List<kotlin.String>
)

data class PairingPreview(
    var pcName: kotlin.String,
    var addresses: List<kotlin.String>,
    var expiresAtMs: kotlin.Long       // by the PC's clock; display only, the PC decides expiry
)

data class NewFile(
    var srcPath: kotlin.String,        // file the app owns; core copies it, the caller deletes it
    var name: kotlin.String,           // display name. Any type: a photo/video extension must match its bytes, every other name (or none) is a plain File. Shortcut and folder-setting names are refused
    var folderId: kotlin.String?,      // null = Inbox
    var capturedAtMs: kotlin.Long,
    var geo: GeoFix?,
    var thumbPath: kotlin.String?,     // JPEG, longest side 512 px, made by the app. Photos and videos only: the core ignores it for a File
    var imported: kotlin.Boolean       // false = camera shot, true = Share > Tugboat
)

data class GeoFix(var lat: kotlin.Double, var lon: kotlin.Double, var accuracyM: kotlin.Double)

data class LocationFix(
    var lat: kotlin.Double, var lon: kotlin.Double, var accuracyM: kotlin.Double,
    var ageMs: kotlin.Long
)

data class SyncStatus(
    var state: SyncState,
    var peerName: kotlin.String?,
    var lastSyncedAt: kotlin.Long?,    // unix ms, "Synced 10s ago"
    var waiting: kotlin.UInt,          // held here, not in the Bin, no receipt from the PC yet ("3 waiting"); nothing is held back for it: items expire on time
    var downloading: kotlin.UInt,      // items that wait on the PC (Pending here)
    var storageLow: kotlin.Boolean,    // 0.2.0: the storage guard is holding downloads back (red banner: "PHONE STORAGE LOW - 37 items wait on the PC")
    var message: kotlin.String?        // one line for REFUSED / PAUSED / "PC NOT TOLD YET ..."
)

data class Settings(
    var binDays: kotlin.UInt,                 // default 7
    var storageGuardBytes: kotlin.ULong,      // default 2 GiB
    var missingPauseFiles: kotlin.UInt,       // PC rescan rule, unused on the phone
    var missingPausePct: kotlin.UInt,         // PC rescan rule, unused on the phone
    var udpPort: kotlin.UShort,               // PC port, unused on the phone
    var maxBlobBytes: kotlin.ULong,           // default 16 GiB
    var stayConnected: kotlin.Boolean         // default true
)
```

```kotlin
enum class FolderKind { INBOX, KEEP, UNSORTED, USER }
enum class MediaKind { IMAGE, VIDEO, FILE }   // FILE (0.2.0) = any other file type: icon tile, no thumbnail
enum class LocalFileState { PENDING, PRESENT, BINNED, PURGED, LOST, REFUSED }

    CAPTURED, ADDED, RECEIVED, MOVED, RENAMED, KEPT, UNKEPT, EDITED, DELETED, BINNED, EXPIRED,
    RESTORED, RETURNED, PURGED, REFUSED, CONFLICT, LOST, FOLDER_CREATED, FOLDER_RENAMED,

sealed class ItemStateInfo {
    data class Deleted(val binnedAtMs: kotlin.Long) : ItemStateInfo()   // in the Bin, user-deleted
    data class Expired(val binnedAtMs: kotlin.Long) : ItemStateInfo()   // in the Bin, expired
    object Kept : ItemStateInfo()        // pinned: "Kept"
    object FolderKeep : ItemStateInfo()  // folder never expires: "Keep"
    data class Live(val expiresAtMs: kotlin.Long) : ItemStateInfo()     // "Expires in 5h"
}

sealed class CaptureRoute {
    data class Place(val placeId: kotlin.String, val folderId: kotlin.String) : CaptureRoute()
    object Unsorted : CaptureRoute()   // places exist, no usable fix: "No location", folder Unsorted
    object Default : CaptureRoute()    // no place applies: the folder on the viewfinder chip (Inbox)
}
```
`SyncState.REFUSED` also means a version mismatch ("Update Tugboat on the PC", in `message`).
`LocalFileState.LOST` = the PC did not have the file when asked (retried automatically).

## Events

```kotlin
interface EventListener { fun onEvent(event: FfiEvent) }

sealed class FfiEvent {
    data class Sync(val status: SyncStatus) : FfiEvent()
    data class ItemsChanged(val ids: List<kotlin.String>) : FfiEvent()  // empty list = unknown set, re-read
    object FoldersChanged : FfiEvent()
    object PlacesChanged : FfiEvent()
    object ActivityAdded : FfiEvent()
    object SettingsChanged : FfiEvent()
    data class PairingCode(val code: kotlin.String, val peerName: kotlin.String) : FfiEvent()  // "482 913"
    data class PairingCompleted(val peerName: kotlin.String) : FfiEvent()
    data class PairingCancelled(val code: kotlin.String, val message: kotlin.String) : FfiEvent()
    object Unpaired : FfiEvent()      // the PC was unpaired here or on the PC
    data class Error(val kind: kotlin.String, val message: kotlin.String) : FfiEvent()
    object Resync : FfiEvent()        // listener fell behind: re-query everything on screen
}
```
- Events carry ids, not rows: re-read through `item`, `items`, `folders`.
- `PairingCancelled.code` is the PairError tag: `expired`, `bad_secret`, `secret_reused`,
  `cancelled`, `confirm_timeout`, `not_open`, `version_mismatch`, `bad_payload`, or a network
  kind (`timeout`, `connect`, `not_local`, ...). `message` is one line, the same text the PC shows.
- `Error` is background failures (a download that failed, a placement problem, a blocked
  non-local connection `not_local`, a log file that cannot be written `log`). Show `message`,
  keep it in the Activity screen's reach. Each is also in the Rust log.
- The PC-only "pairing window open" event is not forwarded.

## Errors

```kotlin
sealed class SnapException(message: String) : kotlin.Exception(message) {
    class InvalidInput(message: String)        // bad id, key not 32 bytes, bad bind address
    class Db(message: String)
    class Io(message: String)                  // source file missing, disk full, permission
    class NewerDatabase(message: String)       // update Tugboat
    class Migration(message: String)
    class NotFound(message: String)
    class InvalidName(message: String)
    class Invalid(message: String)             // rule broken: unknown/deleted folder, restore of a non-Bin item, bad setting
    class NotMedia(message: String)            // a photo/video extension whose bytes are not one (an exe renamed .jpg)
    class Refused(message: String)             // 0.2.0: always-refused name (.lnk .url .scf .library-ms .searchConnector-ms, desktop.ini, autorun.inf) or over 16 GB
    class FileGone(message: String)
    class NotPaired(message: String)
    class AlreadyPaired(message: String)
    class Paused(message: String)
    class NetTimeout(message: String)          // no answer in time: wrong network or PC asleep
    class NetUnreachable(message: String)      // cannot connect (also: local network permission denied)
    class NetNotLocal(message: String)         // address not on the local network, never dialed
    class Net(message: String)
    class Protocol(message: String)
    class VersionMismatch(message: String)     // "Update Tugboat on the PC/phone"
    class PairExpired(message: String)         // "PAIRING CODE EXPIRED - show a new QR"
    class PairBadSecret(message: String)
    class PairSecretReused(message: String)    // "Someone else tried to use this pairing code"
    class PairCancelled(message: String)
    class PairConfirmTimeout(message: String)  // PC owner did not click Pair in time
    class PairNotOpen(message: String)
    class PairVersionMismatch(message: String)
    class PairBadPayload(message: String)      // not a Tugboat pairing code
    class Pairing(message: String)             // any other pairing failure
}
```
Onboarding mapping: `PairBadPayload` = "That is not a Tugboat code" (only this); `PairExpired` = the core's
"PAIRING CODE EXPIRED - show a new QR". The PC opens a NEW pairing window when the old one runs out, so
an old QR can also come back as `PairBadSecret` or `PairNotOpen`: the app reads the payload's expiry
(`inspectPairingPayload`, before dialing) and shows the expired text when its time has passed by the
phone's clock (`Texts.pairFailure(..., codeExpired)`); `PairSecretReused` = "already used"; `NetTimeout` / `NetUnreachable` =
"PC not found: same Wi-Fi? Local network allowed?"; `PairConfirmTimeout`, `PairCancelled` =
retry.

Typed checks pinned by `crates/ffi/tests/phone_flow.rs`: `addFile` of a missing file is `Io`
(message names the file), of an exe renamed `.jpg` is `NotMedia`, of `x.lnk` is `Refused`, into an unknown folder is
`Invalid`; a malformed id is `InvalidInput`; junk to `pairWith` is `PairBadPayload`; `unpair`
with nothing paired is `NotPaired`; `saveSettings` with `binDays = 0` is `Invalid`.

## Name rules (0.2.0)

Top-level functions, the same code the PC runs, so the app keeps no copy of the rules:
`namesExtOf(name)` (lowercase extension or ""), `namesIsRefused(name)`, `namesRefusedText()`.
`ShareNames` calls them through the `NameRules` interface (a JVM test cannot load the .so, so tests
pass a stand-in). `ItemInfo.neverReachedPeer` = in the Bin because it expired before the PC confirmed it
(shown as "NOT ON PC").

## Build

`apps\android\build-rust.cmd` (cmd.exe, from anywhere): host build with the bindgen binary,
`cargo ndk` for arm64-v8a and x86_64 (release; `build-rust.cmd debug` for a debug .so), deletes
stray `libiroh*.so`, regenerates the Kotlin bindings. Needs the Rust Android targets, cargo-ndk
and NDK 30.0.16248370 (or `ANDROID_NDK_HOME`). The .so files and the generated .kt are build
output: add `app/src/main/jniLibs/` and `app/src/main/java/uniffi/` to `.gitignore` if they
should not be committed.

## Testing without a phone: fake PC

`cargo run -p tugboat-core --example fake_pc -- --auto-confirm --advertise 10.0.2.2:47300 --push-dir <dir>`
runs a PC-role core on `127.0.0.1:47300` (the emulator reaches it as `10.0.2.2`). It prints JSON
lines: `payload` (the text for the debug "Paste pairing code" field), `pairing_code`,
`pairing_completed`, `sync`, `received` (a phone file arrived and verified: name, size, path,
blake3), `pushed`, `push_error`, `error`. Files dropped in `--push-dir` go to the phone. Without
`--auto-confirm`, type `y` or `n` and Enter after a code is printed. `--new-pairing` replaces an
existing pairing. Kill it by PID.
